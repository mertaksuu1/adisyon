# Adisyon: Claude için notlar

- Geliştirici başlangıç seviyesinde, Türkçe konuşuyor. Açıklamalar Türkçe ve öğretici olmalı. Kod yorumları Türkçe, kod tanımlayıcıları (sınıf, metot, değişken) İngilizce.
- **Kurulum modeli: önce yerel, bulut sonra.** Restorandaki bir Windows bilgisayar sunucu olur (tek program + SQLite dosyası, Windows servisi); diğer ekranlar yerel ağdan bağlanır. İnternet olmadan çalışmalı. QR menü ve uzaktan rapor ileride bulut modülü olarak gelecek. Geliştirici kurulumu restoranlara kendisi yapacak.
- **Giriş: e-posta yok, yalnızca 4 haneli PIN.** Cihaz bir kez şubenin eşleştirme koduyla eşleştirilir (`/api/auth/pair`, `X-Device-Token`), personel o cihazda PIN'le girer (`/api/auth/pin-login`). PIN'ler `SecretHasher.HashPin` (HMAC) ile saklanır, restoran içinde tekildir; 5 yanlış denemede cihaz 1 dk kilitlenir.
- Yetkiler (`Auth/RoleNames.cs`): menü ürünü ekleme/düzenleme sahip+yönetici+garson; kategori, masa, personel yönetimi sahip+yönetici; masa açma/sipariş mutfak hariç herkes; hesap kapatma sahip+yönetici+kasa; Z raporu ve gün sonu işlemleri yalnızca sahip+yönetici.
- **Sade iş akışı (kullanıcı kararı):** Siparişler çoğunlukla tek bir bilgisayardan (kasa) girilir. Sipariş gönderilince mutfak yazıcısından fiş çıkar; yemek çıkınca mutfak kendi zilini çalar. Mutfak ekranı, "hazırlanıyor/hazır/servis edildi" adımları ve garson bildirimleri YOK; tekrar önermeden önce kullanıcıya sor.
- Ödeme: `POST /api/sessions/{id}/payments` (nakit/kart, tutar boşsa kalanın tamamı, sürüm kontrollü); kalan sıfırlanınca adisyon kendiliğinden kapanır. Ödenmemiş adisyon kapatılamaz. Para üstü yalnızca ekranda hesaplanır.
- İptal/ikram (`/items/{id}/void|comp`, sahip+yönetici+kasa): satır silinmez, işaretlenir (kim/ne zaman; Z raporu için); adet seçilirse satır bölünür (`OrderItem.SplitOff`). İptalde mutfağa İPTAL fişi gider. Toplamlarda yalnızca `IsCharged` satırlar sayılır (SQL'de `VoidedAt == null && CompedAt == null`).
- Masa taşı (`/move`): hedef boşsa taşır, doluysa birleştirir (siparişler ve ödemeler hedefe geçer, kaynak `MergedIntoSessionId` ile kapanır); mutfağa masa değişikliği fişi gider.
- Yönetim kuralları: en az bir aktif sahip kalır; kimse kendini pasife alamaz/rolünü değiştiremez; yönetici sahip/yönetici hesaplarına dokunamaz (kendi PIN'i hariç); şu anki cihazın bağlantısı kesilemez; açık adisyonlu masa kullanım dışı bırakılamaz. Yeni ürün/kategori/masa listenin sonuna eklenir. Yeni eşleştirme kodu eskisini (geliştirmede DEMO-DEMO-DEMO dahil) geçersiz kılar.
- Z raporu (`/api/reports/z?date=`, `/rapor`, sahip+yönetici): iş günü 05:00'te başlar (`Reports/BusinessDay`, sorgularda UTC). Tahsilat = o gün alınan ödemeler; satış = o gün kapanan, birleştirilmemiş adisyonlar; iptal/ikram işlem saatine göre.
- Fişler: `Printing/` altında mutfak fişi (`KitchenTicket`) ve hesap fişi (`BillTicket`, "MALİ DEĞERİ YOKTUR"); ortak biçim `TicketFormat`. Mutfak fişi 48 karakter ve fiyatsız. Yazıcı gelene kadar `PreviewPrinter` (sanal yazıcı, `/fisler` sayfası). Yerel kurulumda API yazıcıya doğrudan gönderir; ayrı yazıcı ajanına gerek yok. SignalR yalnızca `TablesChanged` gönderir (ikinci ekran eklenirse masa planı güncel kalsın).
- Yol haritası: Faz 0 temeller → 1 backend çekirdek → 2 sipariş akışı + mutfak fişi (sanal yazıcı) → 3 kasa/yönetim (ödeme, iptal/ikram, Z raporu) → 4 gerçek ESC/POS yazıcı → 5 AI (Claude API) + raporlar → 6 Windows paketleme + pilot → 7 bulut modülü ve satış.
- Bilinçli olarak YOK: Avalonia, Redis, MediatR, ML.NET. Tüm ekranlar tek React uygulamasında: `/kurulum`, `/giris` (PIN), `/ana-menu` (sahip/yönetici PIN sonrası büyük düğmeli menü; garson/kasa doğrudan `/garson`, mutfak `/fisler`), `/garson` (masa planı), `/garson/masa/:id` (sipariş + hesap kapatma), `/fisler` (fişler), `/rapor` (Z raporu), `/yonetim?sekme=menu|masalar|personel|cihazlar` (sahip+yönetici).
- Kurulum (Faz 6): `scripts/build-package.sh [win-x64|osx-arm64]` → `dist/adisyon-<rid>/` (web `wwwroot` içinde, self-contained). Üretimde tek program `:5000`'de hem API'yi hem ekranları sunar; açılışta migration uygulanır, demo veri yüklenmez. `data/secrets.json` ilk açılışta üretilir (KAYBOLURSA PIN'LER ÇALIŞMAZ, yedeklenmeli); veritabanı `data/adisyon.db`. Boş veritabanında `/kurulum` ilk kurulum sihirbazını gösterir (`/api/setup`, yalnızca hiç restoran yokken çalışır).
- Çoklu kiracı: her tabloda `TenantId` ve EF Core global query filter (yerelde tek kiracı olur ama buluta geçiş için korunuyor). Uç noktalar varsayılan olarak giriş ister; açık olanlar `[AllowAnonymous]`.
- API `http://localhost:5260`, web `http://localhost:5173`; Vite `/api` isteklerini API'ye proxy'ler.
- Windows (6c): `UseWindowsService` ("Adisyon" servisi); veri klasörü Windows'ta `C:\ProgramData\Adisyon`, diğerlerinde programın yanında `data`. `installer/` → `Kur.cmd`/`kur.ps1` (Program Files'a kopyala, servis, güvenlik duvarı 5000, Edge `--app` kısayolu; güncellemede aynı betik), `Kaldir.cmd` (veriyi silmez). `.ps1` BOM'lu UTF-8 + CRLF, `.cmd` ASCII (`.gitattributes: installer/* -text`). Paket: `scripts/build-package.sh win-x64` → `dist/Adisyon-win-x64.zip`. Henüz gerçek Windows'ta denenmedi.
- Yedek (`Hosting/BackupService`): SQLite çevrimiçi yedeği + `secrets.json`, `data/yedekler`, son 30. Otomatik yalnızca üretimde: açılışta son yedek >20 sa ise ve her gün 04:00. `/api/system/backups|info`, Yönetim > Yedekler ve Cihazlar'da yerel ağ adresi.
- **Veritabanı: SQLite** (kullanıcı kararı; tek dosya, ayrı kurulum yok, WAL modu). Docker/PostgreSQL yok. Eşzamanlılık `TableSession.Version` sayacıyla (`BumpSessionVersions`); DateTimeOffset sayı olarak saklanır; tekillik hatası `DbErrors.IsUniqueViolation`. Geliştirme DB'si `src/Adisyon.Api/adisyon-dev.db`.
- Doğrulama: `dotnet test` (geçici SQLite dosyaları), `npm --prefix web run build`, `npm --prefix web run lint`.
